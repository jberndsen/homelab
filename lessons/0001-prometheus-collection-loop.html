HOMELAB MONITORING · LESSON 1

Follow one sample

Your first goal: query a measurement collected inside your own cluster.

Prometheus → HTTP GET /metrics → timestamped samples → local database → PromQL query

Who deploys what?

The repository manually manages bootstrap objects: namespaces, the NAS PV, Argo itself and its ApplicationSet. Argo discovers the monitoring production overlay and deploys the workloads from Git. Its self-healing corrects manual drift in resources it manages. It does not own the bootstrap namespace.

A namespace groups objects; it grants no cross-namespace API access. This first Prometheus has no Kubernetes API token or RBAC grants because self-scraping needs neither.

The collection loop

The scrape configuration is deliberately small:

global:
  scrape_interval: 30s
scrape_configs:
  - job_name: prometheus
    static_configs:
      - targets: ['localhost:9090']

This excerpt shows collection only; the committed file also sets timeout and retention. A target is an HTTP endpoint. A scrape is one retrieval. A sample is a value with a timestamp. A time series is identified by a metric name and its complete set of labels.

Try it

In a terminal, keep this command running:

kubectl -n monitoring port-forward svc/prometheus 9090:9090
  1. Open /metrics. Find prometheus_build_info: these are raw exposed metrics.
  2. Open Targets. Find the prometheus job and its last scrape.
  3. Open Query and evaluate up{job="prometheus"}. Expect 1 after a successful scrape.
  4. Query prometheus_build_info. Inspect its version label. Switch to a graph to see samples over time.

Prometheus creates up to record scrape success. A value of 1 means the endpoint was scraped successfully. It does not prove media playback or downloads work.

Where does history live?

Prometheus writes to /prometheus on the 10 GiB local-path PVC. Pod replacement preserves the claim. Storage loss can destroy history. Retention removes old blocks at seven days or about 7 GiB, whichever comes first; WAL and head data need extra room. Local-path does not impose a per-claim disk quota.

The Deployment uses Recreate to stop the previous writer before starting another. A generated ConfigMap hash changes the Pod template when configuration changes, making Argo roll out the new configuration. PVC annotations require confirmation for Argo prune or deletion; direct Kubernetes deletion bypasses those gates.
